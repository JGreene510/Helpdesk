INSTALL HELPDESK (VERSION 4)  -  STEP BY STEP, FROM ZERO
========================================================

You do not need to know anything about computers to follow this.
Go in order. Do not skip steps. If a step does not do what this page
says it should, go to PART 12 (problems and fixes) near the end.

Time needed: about 20 minutes.

FILL THIS IN AS YOU GO (so you never have to hunt for it later)
--------------------------------------------------------------------

   The Pi's login name  ("PIUSER") ........ ______________________

   The Pi's address     ("PIADDRESS") ...... ______________________
        (looks like  mypi.local  or like  192.168.1.50 )

   The Helpdesk web address (Part 7) ...... http://______________:3000

   Admin username ......................... Beta
   Admin password ......................... (you choose it in Part 8.

--------------------------------------------------------------------
WORDS YOU WILL SEE
--------------------------------------------------------------------

Pi ............ The small computer that will run Helpdesk.
Terminal ...... A window where you type commands instead of clicking.
                On Windows it is called "PowerShell".
Command ....... A line of text you type, then press the Enter key.
Zip file ...... One file that contains many files squeezed together.
Ticket ........ One request for help.
Admin ......... A boss login that can do everything.


--------------------------------------------------------------------
HOW TO READ THE COMMANDS IN THIS GUIDE
--------------------------------------------------------------------

Indented lines like this are things you TYPE (or copy and paste), and
then press Enter:

        like this line

Words in CAPITAL LETTERS (PIUSER, PIADDRESS) are blanks. Swap them
for what you wrote in the box above. Example: if your login name is
"sam" and the address is "mypi.local", then

        ssh PIUSER@PIADDRESS

becomes

        ssh sam@mypi.local

Spaces matter. Type each line exactly as shown.

When you type a password in a terminal, NOTHING appears on the screen
- no dots, no stars. That is normal and it IS working. Type it, then
press Enter.

To paste in PowerShell: right-click once inside the window.


====================================================================
PART 0 - WHAT YOU NEED  (check each one)
====================================================================

[ ] The file  helpdesk-v4.zip  saved on your Windows computer, in the
    Downloads folder. (Do NOT unzip it on Windows. Leave it as is.)

[ ] A Raspberry Pi that is turned on, plugged into your network, and
    connected to the internet. It must already have Ubuntu or
    Raspberry Pi OS installed (the normal system for a Pi).

[ ] The Pi's login name and password (the ones you use to sign in to
    the Pi). If someone else set up your Pi, ask them for these.

[ ] About 20 minutes where nothing else needs your attention.

Using a Mac? Same steps, but open "Terminal" instead of PowerShell,
and in Part 3 use the Mac line shown there.


====================================================================
PART 1 - FIND THE PI'S LOGIN NAME AND ADDRESS
====================================================================

You need two things: the Pi's login name (PIUSER) and the Pi's
address (PIADDRESS). Use the first way that works for you.

WAY 1 - You (or someone) set the Pi up recently
   When a Pi is first set up, a name and a login name are chosen.
   The address is usually that name with ".local" on the end.
   Example: name "mypi" -> address  mypi.local

WAY 2 - Look in your router
   Your router (the box from your internet company) keeps a list of
   everything connected to it. Open a web browser and type the
   router's page, usually one of these:
        192.168.1.1        192.168.0.1        10.0.0.1
   (It is often printed on a sticker on the router, along with the
   password.) Look for a list called "Connected devices", "DHCP
   clients" or "Attached devices". Find a name like  raspberrypi,
   pi, ubuntu  or the name you gave your Pi. Next to it is a number
   like 192.168.1.50 - that is the address.

WAY 3 - Ask the Pi itself
   Plug a screen and keyboard into the Pi and sign in. Then type
   these three commands, one at a time, pressing Enter after each:

        whoami
        hostname
        hostname -I

   "whoami" shows the login name (PIUSER).
   "hostname" shows the name (add .local to make the address).
   "hostname -I" shows the number address, like 192.168.1.50.
   (The number address always works. The .local name sometimes does
   not. If in doubt, use the number.)

Write both in the box at the top of this page.


====================================================================
PART 2 - OPEN POWERSHELL ON YOUR WINDOWS COMPUTER
====================================================================

1. Click the Start button (the Windows logo, bottom of the screen).
2. Type:   PowerShell
3. Press Enter.

A window with text opens. That is where you will type the commands.

Quick test that it can talk to the Pi - type this and press Enter:

        ssh

   * If you see a list starting with "usage: ssh ..." - perfect,
     go to Part 3.
   * If you see "ssh is not recognized" - Windows needs a small
     add-on. Click Start -> Settings -> Apps -> Optional features
     -> "Add a feature", search for  OpenSSH Client , click Install.
     Then close PowerShell, open it again, and repeat the test.


====================================================================
PART 3 - SEND THE ZIP FILE TO THE PI
====================================================================

In PowerShell, type this line (with your blanks filled in) and press
Enter:

        scp "$env:USERPROFILE\Downloads\helpdesk-v4.zip" PIUSER@PIADDRESS:~

(Mac users, type this instead:)

        scp ~/Downloads/helpdesk-v4.zip PIUSER@PIADDRESS:~

What will happen:
   * It may ask:  "Are you sure you want to continue connecting?"
     Type   yes   and press Enter.
   * It asks for the Pi's password. Type it (nothing shows) and press
     Enter.
   * You should see a line ending in  100%  - that means it arrived.

Problem? See PART 12.


====================================================================
PART 4 - LOG IN TO THE PI
====================================================================

Type:

        ssh PIUSER@PIADDRESS

Type the Pi's password again and press Enter.

When you see a line ending in a dollar sign, something like

        sam@mypi:~$

you are "inside" the Pi. Everything you type from now on happens on
the Pi, not on your Windows computer.


====================================================================
PART 5 - UNPACK THE ZIP FILE AND RUN THE SETUP
====================================================================

Type these lines ONE AT A TIME. Press Enter after each one and wait
until you see the dollar-sign line again before typing the next.

        sudo apt install -y unzip

   (It may ask for the Pi's password. It may say "unzip is already
   the newest version" - that is fine.)

        unzip helpdesk-v4.zip

   (Lots of lines scroll by. That is the files being unpacked.)

        cd helpdesk-v4

   (This steps "into" the new folder. Nothing is printed.)

        bash setup.sh

Now the setup runs. It may ask you up to two questions. Type  y  and
press Enter for each:

   "Install nodejs and npm with apt now? [y/N]"  ->  y
        (You only see this if the Pi does not have Node yet. Node is
         the engine Helpdesk runs on.)

   "Install and start the systemd service now? [y/N]"  ->  y
        (This makes Helpdesk start by itself every time the Pi is
         switched on. You want this.)

It may ask for the Pi's password again. Then it works for 2 to 5
minutes. LOTS of scrolling text is normal. Do not close the window.

If setup stops with a red or "ERROR" message, go to PART 12.


====================================================================
PART 6 - WRITE DOWN THE FIRST PASSWORD   (important!)
====================================================================

Near the end of the setup you will see something like this:

   First-run administrator login (shown once; you must change it at
   first login):
      username : Beta
      password : Xk3mQ9vTr2LpWz7a   (one time; you must change it ...)

The password is the jumble of letters and numbers after
"password :". Copy it or write it on paper RIGHT NOW. It is shown
only once. You will replace it in Part 8, so you only need this one
for a few minutes.

(If you missed it - no problem. Go to PART 12, "I missed the first
password".)


====================================================================
PART 7 - OPEN THE HELPDESK WEB PAGE
====================================================================

The last lines of the setup say something like:

        Open  http://192.168.1.50:3000

Write that address in the box at the top of this page.

Now, on ANY computer or phone on the same network (same Wi-Fi or same
cables as the Pi), open a web browser (Chrome, Edge, Safari...). Click
the very top bar of the browser (where web addresses go), type the
address EXACTLY as written, and press Enter.

You should see a page called "Helpdesk" with a form named
"Submit a Support Ticket".

   YES -> good! Go to Part 8.
   NO  -> go to PART 12, "The web page will not open".


====================================================================
PART 8 - LOG IN FOR THE FIRST TIME AND CHOOSE YOUR OWN PASSWORD
====================================================================

1. On the Helpdesk page, click  "Admin Login"  (top right).

2. Username:  Beta
   Password:  the jumble from Part 6.
   Click "Login".

3. A box called "Change Password" appears. You cannot close it - you
   MUST choose a new password. This is on purpose.

      Current Password ... the jumble you just used
      New Password ....... the one you are choosing
      Confirm Password ... the new one again

   Rules for the new password:
      - at least 10 characters
      - must not contain the word "Beta"
      - must not be something very common like  password123

   An easy recipe: join 3 or 4 random words and a number, like
   purple-tractor-lamp-42

   Click "Change Password".

4. You are in. You will see four boxes: Total Tickets, Open, Assigned,
   Resolved. They show 0 for now. That is correct.

Save your new password in a password manager, or on paper in a
locked drawer. Not on a sticky note on the monitor.

Chrome and Edge may ask "Save password?" - clicking Save is fine and
saves you typing it every time.


====================================================================
PART 9 - TEST THAT IT SURVIVES A RESTART  (recommended, 3 minutes)
====================================================================

This proves Helpdesk will come back by itself after a power cut.

1. In PowerShell (still logged in to the Pi) type:

        sudo reboot

   PowerShell will say the connection closed. That is expected.

2. Wait 2 full minutes.

3. Reload the Helpdesk web page (press F5 in the browser).

   The page shows again -> the install is finished and healthy.
   It does not -> go to PART 12, "The web page will not open".

PART 10 - TELL YOUR TEAM
====================================================================

1. Send everyone the web address from Part 7.
   Tip: in the browser, press Ctrl+D to bookmark it.

2. Print or email the file  HOW-TO-GET-HELP.txt  (it is in the zip)
   to the people who will ask for help. It is one page.

3. To add helpers who work on tickets, read START-HERE.txt, Part 1.

====================================================================
PART 11 - OPTIONAL: TURN THE PASSWORD OFF (AND BACK ON)
====================================================================

READ THIS FIRST - what "turn the password off" means here
---------------------------------------------------------
Normally staff must log in with a username and password to see the
tickets. You CAN switch this off so that staff on your own network
just click a button and go straight in. This is called "open access".

What changes when it is ON:
   * A new button, "Staff Console (no password)", appears at the top
     of the Helpdesk page. Clicking it opens the ticket list with no
     login. Staff can read tickets and work on them (assign, change
     status, write resolution notes).
   * The normal "Admin Login" still works and is still needed for
     boss jobs: adding or removing people, resetting passwords, email
     settings, and deleting tickets. These can NEVER be done without
     a password. This is deliberate and cannot be switched off.
   * It only works for computers and phones on YOUR network. Someone
     outside your network still has to log in with a password.
   * It only works when the web address is a number (like
     192.168.1.50:3000) or a short name (like mypi.local:3000). If
     someone opens it through a long web-style name, Helpdesk asks
     for the password. (That is a safety feature.)

The honest warning:
   While it is ON, EVERYONE connected to your network can read every
   ticket - including visitors on your Wi-Fi, guests, and any device
   that joins. Tickets may contain private details. Only use this if
   you trust everybody on that network.

   Never use "port forwarding" on your router for Helpdesk. (If you do
   not know what that is, you have not done it. Good.)

Easier and safer idea:
   If the real problem is "typing the password is annoying", let your
   browser remember it. When Chrome or Edge asks "Save password?",
   click Save. After that, logging in is two clicks.

   (This is about the Helpdesk password. It has nothing to do with the
   Pi's own sign-in password, which stays as it is.)


TO TURN THE PASSWORD OFF  (turn "open access" ON)
-------------------------------------------------
1. Open PowerShell and log in to the Pi:

        ssh PIUSER@PIADDRESS

2. Type these three lines, one at a time, Enter after each. (It may
   ask for the Pi's password.)

        printf '\nOPEN_ACCESS=on\n' | sudo tee -a /etc/helpdesk.env
        sudo chmod 600 /etc/helpdesk.env
        sudo systemctl restart helpdesk

   The first line prints an empty line and then  OPEN_ACCESS=on  back
   at you. That is correct.

3. Wait 10 seconds. Reload the Helpdesk web page (press F5).

4. You should see the new button "Staff Console (no password)" at the
   top. Click it. The ticket list opens with no login, and the top
   bar says "Open".

   No button? Check these in order:
      - You opened the page with a number or short name (see above).
      - You are on the same network as the Pi (not on mobile data).
      - You typed the lines in step 2 exactly, then restarted.


TO TURN THE PASSWORD BACK ON  (turn "open access" OFF)
------------------------------------------------------
1. Log in to the Pi (same as above), then type:

        sudo sed -i '/^OPEN_ACCESS=/d' /etc/helpdesk.env
        sudo systemctl restart helpdesk

   (If it says "No such file or directory", open access was never
   turned on. Nothing to do.)

2. Reload the page. The "Staff Console (no password)" button is gone.
   Everyone must log in again.

PART 12 - PROBLEMS AND FIXES
====================================================================

--------------------------------------------------------------------
"Could not resolve hostname" (when using scp or ssh)
--------------------------------------------------------------------
The ".local" name did not work on your network. Use the Pi's NUMBER
address instead (Part 1, Way 2 or 3), for example:

        ssh sam@192.168.1.50

--------------------------------------------------------------------
"Connection timed out"
--------------------------------------------------------------------
Your computer cannot reach the Pi. Check: Is the Pi switched on? Is
your computer on the same network (same Wi-Fi) as the Pi? Is the
address correct? (Addresses can change - repeat Part 1.)

--------------------------------------------------------------------
"Connection refused"
--------------------------------------------------------------------
The Pi is on, but the "remote sign-in" feature (SSH) is switched off.
Fix it from the Pi itself: plug in a screen and keyboard, sign in,
and type:

        sudo systemctl enable --now ssh

(If it says the "ssh" service does not exist, first type:
        sudo apt install -y openssh-server
and then the line above.)

--------------------------------------------------------------------
"Permission denied, please try again"
--------------------------------------------------------------------
The login name or password is wrong. Check the login name in the box
at the top of this page (Part 1, Way 3: "whoami"). Passwords are
case-sensitive (capital letters matter).

--------------------------------------------------------------------
"WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!"
--------------------------------------------------------------------
This appears if the Pi was wiped and set up again, or a different
Pi now has the same address. If you are sure it is YOUR Pi, type this
in PowerShell (with your PIADDRESS), then try again:

        ssh-keygen -R PIADDRESS

--------------------------------------------------------------------
"unzip: cannot find or open helpdesk-v4.zip"
--------------------------------------------------------------------
You are in the wrong folder on the Pi. Type:

        cd ~
        ls

You should see  helpdesk-v4.zip  in the list. If not, repeat Part 3.

--------------------------------------------------------------------
Setup shows "npm ERR!", "network" or "could not resolve"
--------------------------------------------------------------------
The Pi probably has no internet. Test it:

        ping -c 3 google.com

If you see lines containing "time=", the internet works - run
"bash setup.sh" again. If you see "Name or service not known" or
"100% packet loss", fix the Pi's internet first, then run setup again.

--------------------------------------------------------------------
Setup says Node.js is "still older than 18"
--------------------------------------------------------------------
The Pi's system is too old to get a new enough Node.js from its
normal software list. Ask whoever looks after your Pi to install a
current Node.js "LTS" version from https://nodejs.org, then run
"bash setup.sh" again.

--------------------------------------------------------------------
"I missed the first password"
--------------------------------------------------------------------
Log in to the Pi, go into the folder, and make a new one:

        cd ~/helpdesk-v4
        node server.js --reset-admin

It prints a new one-time password. Use it in Part 8.

--------------------------------------------------------------------
The web page will not open
--------------------------------------------------------------------
Go through these in order:

1. Is the Pi switched on? Wait 2 minutes after plugging it in.

2. Is your computer or phone on the same network as the Pi?

3. Did you type the address exactly? It must start with  http://
   (NOT https) and end with  :3000

4. Log in to the Pi and check that Helpdesk is running:

        sudo systemctl status helpdesk

   You want the words  active (running)  in green. Press the  q  key
   to leave that screen.

5. If it is not running, start it:

        sudo systemctl restart helpdesk

   Wait 10 seconds and try the page again.

6. It works on the Pi's own screen but not from other computers? The
   Pi may have a "firewall" turned on. Check:

        sudo ufw status

   If it says  Status: active , type this, then try again:

        sudo ufw allow 3000/tcp

7. It worked yesterday but not today? The Pi's number address may
   have changed after a power cut. Repeat Part 1 to find the new one,
   or ask whoever looks after your router to "reserve" the Pi's
   address so it never changes.

8. Still stuck? See what Helpdesk wrote in its log:

        sudo journalctl -u helpdesk -n 50 --no-pager

   Copy that text and send it to whoever helps you with computers.

--------------------------------------------------------------------
"EADDRINUSE" or "address already in use" in the log
--------------------------------------------------------------------
Another program on the Pi is already using the number 3000. Easiest
fix: tell Helpdesk to use a different number, for example 3001:

        printf '\nPORT=3001\n' | sudo tee -a /etc/helpdesk.env
        sudo systemctl restart helpdesk

Then your web address ends with  :3001  instead of  :3000.

--------------------------------------------------------------------
"Too many failed logins. Try again later."
--------------------------------------------------------------------
Too many wrong passwords in a row. Wait 15 minutes. (Or use
"I missed the first password" above to get a fresh one.)

PART 13 - UPDATING TO A NEWER VERSION  (keeps tickets and logins)
====================================================================

Updating has its own guide now, with every step spelled out:

        Update.txt

It covers both cases:
   - moving from the old version 3 to version 4 (one time), and
   - every later update, which is ONE command:   bash update.sh

Your tickets, logins and email settings are never inside the zip,
so updating never touches them.

HOW TO SEE WHICH VERSION YOU HAVE: open the Helpdesk web page. The
version is in small letters next to the word Helpdesk at the top,
like   v4.0.0
